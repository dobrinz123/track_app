## Deviations / documented interpretation decisions (not scope changes)

1. **F5 unit wiring bypasses the screens** — `ActiveDashboardScreen.tsx` and `CircuitDetailScreen.tsx` are the natural place to pass `units` as a prop to `CoachStrip`/`CornersList`, but neither is in the WRITE SET. Instead, both components subscribe to `settingsStore` internally via the existing `useSettings` hook (same pattern already used by every screen). This keeps every change inside the write set; it does add a new session-layer dependency to two `ui/components` files (pre-existing precedent: every `ui/screens/*` already imports `session/composition` directly).
2. **F1/F2 "2s hold ONLY for identical-corner flicker"** — implemented as a flat 2000ms grace window (down from 5000ms), not literally conditioned on "is this the identical corner" (which would require seeing the future). A genuinely different corner's cue always replaces the held one immediately regardless of the hold, so the hold's only observable effect is exactly the flicker-bridging described. See sessionController.ts:102-113 doc comment.
3. **CORNER_ANALYSIS_VERSION bump 2→3** — the ticket explicitly sanctions this exact escape hatch; documented at length in contracts.ts and analyzeCorners.test.ts. The change is a genuine correctness fix (verified merged-corner bug), not a regression.
